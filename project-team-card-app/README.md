## 코드 리펙토링 내용

```
저는 지금까지 개발을 모두 SwiftUI로 해왔어서, 처음에 UIkit를 활용한 프로젝트 설계구조를 이해하기 어려웠습니다..
그래서 개인적으로 공부한 것, 팀원들과 나운 대회를 토대로 "나만의 스타일로 새롭게 구조를 설계해보고 프로젝트를 완성해보자"라는
이유로 코드 리펙토링을 진행하게 됐습니다!
```

### 주요 키워드
- 폴더링 및 기능 별 책임분리
- 컴포넌트의 커스텀화
- 다른 팀원이 작성한 코드를 이해하고, 본인 만의 스타일로 변경
- 코드의 최적화(고차함수 적극 활용)

### 1. 폴더링 및 기능 별 책임분리
- 한 곳에 몰아져 있던 코드를 파일별로 분리하고 폴더별로 정리
- 단일 책임 원칙을 고수해 기능별로 메서드 모듈화(이 부분은 특히나 자신이 없어서 주의깊게 봐주시고 피드백 해주시면 감사하겠습니다!)

### 2. 컴포넌트의 커스텀화
- 이전에 SwiftUI에서 개발할 때에는 여러 뷰에서 재사용 가능성이 있는 컴포넌트들을 커스텀화해서 사용했습니다.
- 그래서 이번 프로젝트도 비슷하게 적용해봤는데 이렇게 설계하는 것이 관습적으로 권장되는지, 아니면 다른 방법이 있는지 궁금합니다.

### 3. 다른 팀원이 작성한 코드를 이해하고, 본인 만의 스타일로 변경
- 개개인의 템플릿 코드를 제외하고는 모두 코드를 수정했습니다.
- 팀원들끼리 시간상의 이유로 코드리뷰를 진행을 못해서 팀이 바뀐 이후에도 이전 팀원들에게 코드의 이해를 구하러 다녔습니다..
- 그렇게 코드 작성이유를 모두 들은 뒤에 저만의 방법으로 다른 분들의 코드를 수정해가며, 전체적인 흐름을 이해할 수 있었습니다.

### 4. 코드의 최적화(고차함수 적극 활용)
- 불필요한 변수선언과 쓸데 없이 길다고 판단되는 코드들은 고차함수를 활용해 보다 간결하게 수정했습니다.
- 고차함수는 내부적으로 최적화가 잘되있다고 알고 있어서 성능적인 면에서도 더 유리하겠다고 생각했습니다.

### 5. ETC
- 리펙토링 후에도 코드가 완성도가 부족하다고 스스로 생각하고 있습니다. 
- 최대한 제 스타일을 유지하면서 좋은 것만 흡수해서 적용하고 싶습니다.
- 하지만 제 여러 스타일 중 어떤 것은 아예 권장되지 않을 수도 있다고 생각하기 때문에 열려있는 마음으로 피드백을 받겠습니다!
